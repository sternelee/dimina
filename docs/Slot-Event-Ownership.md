# 插槽事件归属

## 归属规则

插槽中的节点属于声明它的页面或组件。即使节点显示在另一个组件内部，事件处理函数仍在声明者实例上执行。

例如，弹框组件声明关闭按钮，再通过动画组件的插槽展示按钮。点击时应调用弹框组件的 `closePopup`，动画组件自身的节点则使用动画组件的事件上下文。

事件归属决定处理函数在哪个实例上执行；冒泡和捕获决定事件的传播范围，两者分别处理。CSS 作用域不参与事件归属判断。

## 上下文解析

基础组件在 setup 中调用 [useInfo](../fe/packages/components/src/common/events.js)，取得 `bridgeId`、`moduleId`、`path` 和事件绑定属性。

1. 读取渲染父级注入的路径和模块信息，作为默认上下文。
2. 从 `vnode.ctx` 取得节点的声明上下文。
3. 对没有自身事件上下文的透传组件，继续沿声明链查找。只有组件自身明确提供 `path` 才构成事件上下文边界，`theme` 等无关依赖不会改变归属。
4. 使用声明者的模块信息；没有可用的声明上下文时，使用默认上下文。
5. 声明上下文与渲染父级不同时，向内部节点提供正确的路径和模块信息。

上下文比较同时检查路径和模块信息对象。同一路径的不同组件实例仍保持各自的事件归属。

这一规则符合 [Vue 插槽作用域](https://vuejs.org/guide/components/slots.html#render-scope)的语义。实现使用 `vnode.ctx` 和 `provides`，升级 Vue 时需验证相关内部结构及回归用例。

## 事件派发与性能

上下文解析只在组件初始化时执行。事件处理逻辑复用已解析的 `moduleId`，点击和触摸移动时无需重新遍历声明链。

普通节点复用父级的 `provides`；只有跨作用域时才创建必要的上下文覆盖，减少组件初始化时的对象分配。实现不维护全局模块缓存，上下文随组件实例管理。

## 回归覆盖

[插槽事件测试](../fe/packages/components/__tests__/slot-event-owner.spec.js)覆盖：

- 直接插槽、view 包装、cover-view 包装及嵌套包装中的关闭事件。
- 透传组件自身节点上的事件绑定。
- 透传组件提供主题等无关依赖时的事件归属。
- 接收插槽的组件自身节点使用自身事件上下文。

涉及声明上下文、透传组件或 Vue 版本的变更，应运行这些用例及基础组件、渲染层测试，并验证真实页面的弹框打开和关闭行为。
